# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `fed-infra`, `active-fed` and `fed-twin` CI that gates every change, contract testing that catches cross-repo breakage without a cluster, a nightly smoke test on a real kind cluster, and CD that publishes images to GHCR — then validate all of it against real runs.

**Architecture:** Four tiers, each placed where it can actually run (unit → contract → smoke → manual gate). CI never inlines commands; it invokes Makefile targets, so what CI runs is reproducible on a laptop. Cross-repo coupling is verified in both directions: fed-infra nightly-tests both consumers' contracts, and each consumer PR-tests its pinned submodule.

**Tech Stack:** GitHub Actions, GNU make, bats, pytest, ruff, shellcheck, kind, Docker Buildx, GHCR.

**Spec:** `docs/superpowers/specs/2026-08-20-cicd-design.md` (in `active-fed`)

## Global Constraints

- **Three separate repos**, each with its own git history and remote. Work on `main` in each. Conventional Commits, **no trailers**.
- **Do not push until Task 8.** Tasks 1–7 commit locally only. Task 8 is the explicit, user-authorised validation push.
- **`fed-infra` MUST NOT contain the strings `active-fed` or `fed-twin`** — enforced by `tests/agnostic.bats`, docs included. Task 5 fetches consumer contracts at runtime; it must not commit them.
- **`lib/*.sh` never sets shell options** (`set -euo pipefail` leaks into callers); `bin/*` and `tests/stubs/*` do set them.
- **Guard command substitutions**: `x=$(...) || x=""`. A bare `x=$(pipeline)` under a caller's errexit aborts before its own fallback runs.
- **`tests/lint_inert_assertions.py`** fails any non-final `[[ ]]` in a bats test lacking `|| return 1`.
- **Report exit codes unpiped.** `make check | tail` reports `tail`'s status. Use `make check > /tmp/x.log 2>&1; echo $?`.
- Repos: `https://github.com/supat-roong/{fed-infra,active-fed,fed-twin}`.
- **Verified tool facts** (measured 2026-08-20, do not re-derive): `make lint` in fed-twin uses ruff 0.15.5 over `src/ tests/` and passes; its CI used `uvx ruff check .` (ruff 0.16.3, whole repo) and produced 72 errors. An explicit `select` insulates against version drift — active-fed's config passes under both 0.15.4 and 0.16.3. `ruff format --check` is **not** stable: it would reformat 13 files in active-fed and 16 in fed-twin, so **no format gate is introduced by this plan**.

### Task 1: fed-twin — explicit lint configuration and remediation

fed-twin's CI is red for two independent reasons: it invokes `uvx ruff` (unpinned; resolves 0.16.3, whose defaults enable rule families the project never selected) over `.` instead of `src/ tests/`. Its own `make lint` passes. This task makes the configuration explicit so neither cause can recur.

**Files:**
- Modify: `fed-twin/pyproject.toml`
- Modify: various under `fed-twin/src/` (mechanical lint fixes)

**Interfaces:**
- Produces: `make lint` in fed-twin passes under **both** the pinned ruff and the latest release.

- [ ] **Step 1: Record the current failure count**

```bash
cd fed-twin
uvx ruff check src/ tests/ --isolated --select E,F,I,UP --line-length 120 --output-format=concise | wc -l
```
Expected: `47` lines — 28 I001, 11 UP015, 1 UP008 (all autofixable) and 7 E501 (manual). Note the number; Step 5 must reach 0.

- [ ] **Step 2: Add the explicit ruff configuration**

Append to `fed-twin/pyproject.toml`:

```toml
[tool.ruff]
line-length = 120
target-version = "py310"

[tool.ruff.lint]
# Matches active-fed's selection, which was verified to produce identical
# results under ruff 0.15.4 and 0.16.3 -- an explicit select is what stops a
# ruff upgrade from turning CI red with no code change. Without this file,
# `ruff check` inherits whatever defaults the installed version ships: 0.15.5
# passed, 0.16.3 raised 72 findings from rule families this project never
# opted into (BLE001, S110, PLW1510 and friends).
#
# line-length is 120 rather than active-fed's 100: the long lines are almost
# all inside KFP component bodies that embed shell and YAML, where wrapping
# hurts readability. 100 would mean 40 manual edits in FL code unrelated to
# CI; 120 means 7.
select = ["E", "F", "I", "UP"]
```

- [ ] **Step 3: Apply the mechanical fixes**

```bash
cd fed-twin
uv run ruff check src/ tests/ --fix
```
Expected: 40 fixed (import sorting, redundant `open()` modes, one `super()` call). Review the diff — these are safe, but confirm no import removal changed behaviour in `src/core/`.

- [ ] **Step 4: Fix the 7 remaining long lines by hand**

```bash
uv run ruff check src/ tests/ --output-format=concise
```
Wrap each reported line. Do **not** add `# noqa`; do not raise `line-length` further.

- [ ] **Step 5: Verify under both ruff versions**

```bash
cd fed-twin
make lint                                   # pinned ruff 0.15.5
uvx ruff check src/ tests/                  # latest, reads the new config
uv run pytest tests/ -q                     # 28 tests, unchanged
```
Expected: both lint runs report `All checks passed!`; 28 tests pass.

- [ ] **Step 6: Commit**

```bash
git add pyproject.toml src/ tests/
git commit -m "fix(lint): pin an explicit ruff rule set and clear the findings

CI ran uvx ruff (unpinned, resolving 0.16.3) over the whole repo while the
Makefile ran the project's pinned 0.15.5 over src/ tests/ -- so CI enforced
rule families the project never selected and had never been green. An
explicit select fixes the class: verified identical under 0.15.4 and 0.16.3."
```

### Task 2: `make ci` and `make contracts` in all three repos

The rule that keeps CI honest: **workflows invoke Makefile targets, never inline commands.** fed-twin's drift happened precisely because `uvx ruff check .` lived only in YAML where nobody ran it.

**Files:**
- Modify: `fed-infra/Makefile`, `active-fed/Makefile`, `fed-twin/Makefile`

**Interfaces:**
- Produces: `make ci` (tier 1) and `make contracts` (tier 2) in every repo. Tasks 3–5 call only these.

- [ ] **Step 1: fed-infra — add the targets**

Replace `fed-infra/Makefile` with:

```make
.PHONY: test lint check ci contracts
test:
	bats tests/
lint:
	shellcheck -x -P SCRIPTDIR $$(find bin -type f 2>/dev/null) lib/*.sh tests/stubs/*
check: lint test
# Tier 1: exactly what CI runs per PR. Kept identical to `check` so a
# developer and a runner cannot diverge.
ci: check
# Tier 2: render every contract this repo owns without touching a cluster.
# --dry-run performs no real side effects (enforced by tests/components.bats)
# but exercises config validation, the template whitelist and every
# component's dispatch path.
contracts:
	@set -e; for env in tests/fixtures/*.env; do \
		echo "=== dry-run $$env ==="; \
		out=$$(mktemp -d); \
		bin/fed-infra-up --env "$$env" --dry-run --render-dir "$$out"; \
		test -n "$$(ls -A $$out)" || { echo "FAIL: $$env rendered nothing"; exit 1; }; \
		rm -rf "$$out"; \
	done
```

- [ ] **Step 2: Verify fed-infra's targets**

```bash
cd fed-infra
make ci > /tmp/ci.log 2>&1; echo "ci exit: $?"
make contracts > /tmp/contracts.log 2>&1; echo "contracts exit: $?"
```
Expected: both `0`. `contracts` prints three `=== dry-run ... ===` headers (consumer-a, consumer-b, consumer-c).

- [ ] **Step 3: active-fed — add the targets**

Add to `active-fed/Makefile`:

```make

# Tier 2: dry-run this consumer's real contracts against the pinned
# vendor/fed-infra. Catches a submodule bump that breaks our contracts before
# it reaches a cluster -- the class of defect that cost the most time in P3
# (a karmada component that gated nothing, a renamed port variable, member_prefix
# drifting from FED_MEMBER_PREFIX).
contracts:
	@set -e; for env in infra.env infra.env.multi; do \
		echo "=== dry-run $$env ==="; \
		out=$$(mktemp -d); \
		bash vendor/fed-infra/bin/fed-infra-up --env "$$env" --dry-run --render-dir "$$out"; \
		test -n "$$(ls -A $$out)" || { echo "FAIL: $$env rendered nothing"; exit 1; }; \
		rm -rf "$$out"; \
	done
```

Add `ci contracts` to the `.PHONY` line.

### Task 5: Cross-repo — fed-infra nightly-tests both consumers' contracts

Catches a library change that breaks a consumer **in the repo that caused it**, before anyone bumps a submodule. This is the direction that would have caught the `karmada`-component validation and the `FED_KARMADA_DASHBOARD_PORT` rename.

**Files:**
- Modify: `fed-infra/.github/workflows/ci.yml`

**Interfaces:**
- Consumes: consumer contracts fetched at runtime (never committed — `tests/agnostic.bats` forbids consumer strings in this repo)

- [ ] **Step 1: Add the job**

Append to `fed-infra/.github/workflows/ci.yml`:

```yaml
  consumer-contracts:
    # Nightly only. Fetches each consumer's real contract and renders it
    # against this repo's current main, so a library change that breaks a
    # consumer fails here rather than surfacing days later in a submodule bump.
    #
    # Contracts are fetched at runtime, never committed: this repo must not
    # contain consumer identifiers (tests/agnostic.bats), and a checked-in copy
    # would drift from the real one -- which is the exact failure this job exists
    # to catch.
    if: github.event_name == 'schedule'
    runs-on: ubuntu-latest
    timeout-minutes: 15
    strategy:
      fail-fast: false
      matrix:
        consumer:
          - { repo: "supat-roong/active-fed", envs: "infra.env infra.env.multi" }
          - { repo: "supat-roong/fed-twin",   envs: "infra.env infra.env.multi" }
    steps:
      - uses: actions/checkout@v4
      - name: Install envsubst
        run: sudo apt-get update && sudo apt-get install -y gettext-base
      - name: Fetch the consumer's contracts
        run: |
          set -euo pipefail
          git clone --depth 1 --filter=blob:none --sparse \
            "https://github.com/${{ matrix.consumer.repo }}.git" /tmp/consumer
          cd /tmp/consumer && git sparse-checkout set --no-cone '/*.env*'
          ls -la /tmp/consumer
      - name: Render each contract against this fed-infra
        run: |
          set -euo pipefail
          for env in ${{ matrix.consumer.envs }}; do
            src="/tmp/consumer/$env"
            if [ ! -f "$src" ]; then
              echo "consumer has no $env; skipping"
              continue
            fi
            echo "=== $env ==="
            out=$(mktemp -d)
            bin/fed-infra-up --env "$src" --dry-run --render-dir "$out"
            test -n "$(ls -A "$out")" || { echo "FAIL: $env rendered nothing"; exit 1; }
          done
```

- [ ] **Step 2: Rehearse the fetch-and-render locally**

### Task 6: Tier 3 — harden the smoke job

fed-infra's `smoke` job has never executed. A single-cluster stack used ~33 GB of Docker disk locally; a GitHub runner has far less, so it needs disk reclamation and must **measure** what it has.

**Files:**
- Modify: `fed-infra/.github/workflows/ci.yml`

- [ ] **Step 1: Replace the smoke job**

```yaml
  smoke:
    # Nightly only -- brings up a real kind cluster, far too slow for PRs.
    if: github.event_name == 'schedule'
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - name: Report disk before reclamation
        # The design doc records the runner's free disk as UNVERIFIED. This
        # step is how we find out; adjust the component set below if it is
        # tighter than the stack needs.
        run: df -h /
      - name: Reclaim runner disk
        run: |
          sudo rm -rf /usr/share/dotnet /usr/local/lib/android /opt/ghc \
                      /usr/local/share/boost "$AGENT_TOOLSDIRECTORY" || true
          df -h /
      - uses: helm/kind-action@v1
        with:
          install_only: true
      - name: Install envsubst
        run: sudo apt-get update && sudo apt-get install -y gettext-base
      - name: Bring up the single profile
        run: bin/fed-infra-up --env tests/fixtures/consumer-a.env
      - name: Verify core workloads are running
        run: |
          kubectl get pods -n consumer-a
          kubectl wait --for=condition=available deployment/mlflow-server \
            -n consumer-a --timeout=300s
      - name: Verify the run is idempotent
        # fed-infra-up must be safely re-runnable; this is not decorative.
        # A helm field-manager conflict made it non-idempotent during P3 and
        # only a re-run exposed it.
        run: bin/fed-infra-up --env tests/fixtures/consumer-a.env
      - name: Report disk after
        if: always()
        run: df -h /
      - name: Tear down
        if: always()
        run: bin/fed-infra-down --env tests/fixtures/consumer-a.env
```

## Out of scope

- Deploying to any environment; there is no target.
- Multi-arch images.
- Self-hosted runners.
- Tier 4 (full stack, multi-cluster) automation — stays manual, documented in `docs/superpowers/gates/`.
- A `ruff format` gate: neither repo is formatted to ruff's standard (13 files in active-fed, 16 in fed-twin), so enforcing it means a whole-tree reformat — a separate, deliberate decision.
- Coverage thresholds and required-reviewer policy — revisit once the pipelines have a known failure rate.
